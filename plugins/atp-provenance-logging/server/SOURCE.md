# Source of server/ and ui/

Synced from the Prove repository at commit `f564252` (2026-11-20), which
includes harness step capture (`/ingest/trajectory`, step tables,
`self_reported` on `/log`) and the explicit schema upgrade path.

Copied unchanged: `provenance_service.py`, `provenance_schema.py`, `ui/app.css`.

Changed for this public plugin build:

| File | Change |
|---|---|
| `trajectory.py` | Content keys also cover `new_source` (NotebookEdit) and `file_text`/`new_str`/`old_str`. Tool arguments under a content key (`content`, `new_string`, ...) are kept only as a digest whatever their type, and are not JSON-decoded first, so writing a JSON file never stores its values and the digest is the file text's. Prove main has the same gap. |
| `atp_hooks.py` | Cursor state goes to `PROVENANCE_STATE_DIR` (the plugin data folder, one subfolder per destination ledger) instead of the plugin folder, which is replaced on update. `instruction_hash` hashes the working project's `CLAUDE.md`, not this folder's. Transcript chunks are masked for credential shapes before sending (same length, so offsets hold; `trajectory.py chain` must be run on a masked copy) capped at 400 records so the service's 500-record limit never stalls capture, a single record over 512 KiB gets one read of up to 1 MiB, a sub-agent transcript that fails at SubagentStop is retried by later hooks, with `PROVENANCE_STRICT=1` a prompt is refused (exit 2) when registration or transcript capture fails, a Stop that continues after another Stop hook still captures, and if the ledger already holds this session's trajectory under another root the new root captures under `<session_id>@<root prefix>`. |
| `provenance_http.py` | Loopback requests bypass environment proxies (`HTTP_PROXY`), so offline mode cannot leak through one. |
| `provenance_core.py` | `/runtime/metadata` `artifact_hash` also looks for the dashboard at `../ui/app.js`. |
| `hosted_service.py` | Serves the network-free dashboard from `../ui`, including `vendor/`. |
| `manifest.py` | `EMITTERS` lists only what this plugin emits; private-stack sources removed. The `routing_memory` derived fields and collision entry are left out of the public build. Self-test examples use generic names. |
| `ui/app.js` | Simulation agent profiles and sample paths use generic names. The service URL defaults to the page's own origin when served over HTTP(S). Imported/live chain entries keep the service's `actor`, `status`, `error`, `phase` and recorded `input` instead of deriving them from `result`, `action_type` and `target`. A service chain's integrity check passes only on the service's own `/verify` verdict for that chain (an import clears any earlier verdict); an import with no service shows a warning, not a pass. |
| `ui/index.html` | From `atp-mission-control.html`; loads React from `vendor/` instead of a CDN. |

Not included: the MCP server (`provenance_mcp.py`, needs the `mcp` package),
the worker proxy (`provenance_proxy.py`), the repo's `launch.sh` (replaced by
`scripts/prove_local.py`), and anything belonging to the private build
(Sentinel, Oracle, routing, full secure auth).

`ui/vendor/react*.production.min.js` are the unmodified UMD builds from the
`react@18.3.1` and `react-dom@18.3.1` npm packages; checksums in
`ui/vendor/SHA256SUMS`. `ui/prove-offline.html` is generated by
`scripts/build_offline.py`.

When syncing again, run Prove's test suite against this folder and
`python3 -m unittest discover -s plugins/atp-provenance-logging/tests`.
